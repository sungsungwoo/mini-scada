# Mini SCADA for Facility Monitoring IA 문서 (v1.0)

## 1. 문서 목적

본 문서는 **Mini SCADA for Facility Monitoring**의 화면 구조, 메뉴 체계, 사용자별 접근 범위, 주요 화면 간 이동 흐름을 정의한다.
PRD에서 정의된 **운영자(Operator)** 와 **관리자(Admin)** 의 역할 차이와, Usecase에서 정의된 핵심 시나리오를 실제 화면 구조로 연결하는 것을 목표로 한다.

---

## 2. IA 설계 원칙

### 2.1 역할 기반 분리
* **운영자(Operator)** 는 실시간 모니터링과 알람 대응 중심으로 사용한다.
* **관리자(Admin)** 는 설비 등록, Tag 매핑, 임계값 및 데이터 정책 관리 중심으로 사용한다.

### 2.2 모니터링 우선 구조
* 로그인 이후 가장 먼저 진입하는 핵심 화면은 **대시보드**다.
* 설비 상태 확인 → 이상 감지 → 상세 분석 → 알람 대응 흐름이 자연스럽게 이어져야 한다.

### 2.3 실시간성과 재조회 복구 동시 지원
* 실시간 상태는 MQTT 기반으로 반영되지만, 화면 구조는 항상 **재조회 기반 복구**가 가능해야 한다.
* 따라서 상세/목록/이력 화면은 모두 독립 URL과 재진입 가능한 구조를 가진다.

### 2.4 객체 중심 구조
본 서비스의 핵심 객체는 아래와 같다.
* **Device**: 물리 설비 단위
* **Tag**: 설비 내 수집 대상 센서 단위
* **Alarm**: 임계값 초과 또는 통신 장애 이벤트
* **Policy**: 임계값/보존/수집 정책 설정 대상

## 3. 사용자 유형 및 접근 범위

### 3.1 운영자 (Operator)
접근 가능 메뉴:
* 대시보드
* 설비 상세
* 알람 이력
* 알람 상세 / Ack 처리
* **예외 화면 (404 Not Found)**

접근 제한 메뉴 **(접근 시 403 Forbidden 노출)**:
* 설비 등록/수정/삭제
* Tag 매핑 및 임계값 설정
* 데이터 정책 설정

### 3.2 관리자 (Admin)
접근 가능 메뉴:
* 운영자 메뉴 전체
* 설비 관리
* 설비 등록/수정
* Tag 매핑 및 알람 임계값 통합 설정
* 데이터 정책 설정

## 5. 내비게이션 구조

### 5.1 공통 구조

로그인 후 기본 레이아웃은 다음과 같이 구성한다.

```text
[상단 바]
- 서비스명 / 현재 사용자 / 로그아웃
- (선택 사항) System Health 요약 표시
- 브레드크럼(Breadcrumbs) 영역 (예: 설비 관리 > Boiler-01 > Tag 설정) ⭐️

[좌측 사이드바]
- 대시보드
- 알람 이력
- (관리자만) 설비 관리
- (관리자만) 데이터 정책
```

### 5.2 상단 바 역할

* 현재 접속 사용자 정보 표시
* 로그아웃 기능 제공
* **[UX 편의] 브레드크럼(Breadcrumbs)을 제공하여 뎁스(Depth)가 깊은 관리자 화면에서도 현재 위치를 명확히 인지하고 상위 메뉴로 쉽게 이동할 수 있도록 지원한다.**
* System Health 상태 표시는 선택 사항이며, MQTT 브로커 / 백엔드 API / TSDB 연결 상태를 요약 표시하는 운영 편의용 보조 기능으로 정의한다.

### 5.3 좌측 사이드바 역할

* 주요 1차 메뉴 접근
* 운영자/관리자 권한에 따라 메뉴 노출 차등 적용

## 6. 화면 구조 정의

## 6.1 로그인 및 공통 예외 화면

### 목적
사용자가 시스템에 인증 후 진입하도록 하며, 비정상적인 접근을 제어한다.

### 주요 화면
* `/login` : ID / Password 입력 및 인증
* **`/403` : 운영자 권한으로 관리자 메뉴 접근 시 노출 (대시보드로 돌아가기 버튼 제공)**
* **`/404` : 잘못된 URL 입력 시 노출 (대시보드로 돌아가기 버튼 제공)**

---

## 6.2 대시보드

### 목적
전체 설비의 현재 상태를 실시간으로 한눈에 파악하는 핵심 화면

### 주요 정보
* 설비 카드 또는 테이블 목록
* 설비명 / 주요 센서 값 / Online, Offline 상태
* 알람 상태 (Normal / Warning / Critical) / 마지막 수신 시각 (`last_seen`)

### 주요 액션
* 설비 선택 → 설비 상세 이동
* 알람 클릭 → 알람 이력 또는 알람 상세 이동
* [Quick Ack] 미니 알람 패널에서 활성 알람에 대해 즉시 인지 처리

### Quick Ack 제약 및 시각적 피드백 ⭐️
* Quick Ack는 `미인지(Unacknowledged)` 상태의 활성 알람에 대해서만 제공한다.
* Quick Ack는 단건 처리만 지원하며, 상세 사유 입력 없이 “인지 확인”만 수행한다.
* 다중 선택 일괄 처리(Bulk Ack)는 알람 이력 화면에서만 지원한다.
* **[UX 시나리오] Quick Ack 처리된 알람은 미니 패널 목록에서 즉시 사라지거나(숨김 처리), 시각적으로 비활성화(회색 음영 및 취소선 등)되어 운영자가 '처리 완료'를 직관적으로 인지할 수 있게 한다.**

### 화면 내 구성
```text
[상단 요약 영역]
- 전체 설비 수 / Online 수, Offline 수 / Warning 수, Critical 수

[본체]
- 설비 상태 카드/테이블 목록
- 실시간 미니 알람 패널 (Quick Ack 지원)
```

---

## 6.3 설비 상세 화면

### 목적
단일 설비의 상태를 실시간 수치와 시계열 추세로 분석한다.

### 주요 정보
* 설비 기본 정보 / 현재 통신 상태
* Tag별 현재 값 / 실시간 게이지 / 최근 N시간 트렌드 차트 / 최근 알람 및 장애 로그

### 주요 액션
* 조회 시간 범위 변경 / 특정 Tag 필터 / 관련 알람 상세 보기

### 비고
* Offline 상태에서는 마지막 수집값을 유지하되 stale 상태를 시각적으로 구분한다.

---

## 6.4 알람 이력 화면

### 목적
발생한 알람을 목록으로 조회하고 Ack 처리한다.

### 주요 액션
* 알람 상세 보기
* Ack 처리 (단건 Ack 및 다중 선택 후 일괄 Bulk Ack 지원)
* 필터링 (레벨별, 미인지 여부, 설비별, 기간별)

---

## 6.5 알람 상세 화면

### 목적
특정 알람의 원인과 상태를 상세히 확인한다.

### 주요 액션
* Ack 처리 / 설비 상세로 이동

---

## 6.6 설비 관리 목록 화면 (관리자)

### 목적
등록된 설비 목록을 관리하고 신규 설비 추가 및 수정 진입점을 제공한다.

### 주요 액션
* 신규 등록 / 수정 / 삭제
* 상세 설정 이동 (Tag 및 임계값 설정)

---

## 6.7 설비 등록 화면 (관리자)

### 목적
신규 설비를 등록하고 통신 가능한 기본 정보를 설정한다.

### 주요 액션
* 통신 테스트 (저장 전 사전 검증 UX) / 저장 / 취소

---

## 6.8 설비 수정 화면 (관리자)

### 목적
기존 설비의 네트워크 정보 및 Polling 설정을 변경한다.

---

## 6.9 Tag 및 알람 임계값 통합 설정 화면 (관리자)

### 목적
각 설비에서 수집할 센서 항목(Register)을 매핑하고, 해당 센서의 알람 발생 기준(임계값)을 한 번에 설정한다.

### 주요 정보/입력
* **[Tag 기본 정보]: Tag명, Register 주소, Function Code, 데이터 타입, Byte Swap/Word Swap(엔디안 매핑 설정) ⭐️, 단위(Unit)**
* **[알람 임계값 정보]:** Warning 기준값, Critical 기준값, Deadband(Hysteresis) 값
* 표시 순서

### 주요 액션
* Tag 추가 (임계값 설정 포함) / Tag 수정 / 삭제

### 화면 내 구성
```text
[상단]
- 대상 설비 정보

[본문]
- Tag 목록 테이블 (Tag 정보 및 설정된 임계값 요약 표시)
- 우측 또는 모달에서 Tag 및 임계값 통합 추가/수정 폼
```

### 비고
* **다양한 제조사의 Modbus 장비와 정확히 통신하기 위해, 32-bit 이상 데이터 파싱 시 필수적인 바이트 순서(Endianness) 스왑 설정을 제공한다.**
* 사용자 편의성을 위해 Tag(센서) 정보와 알람 임계값 정책을 물리적으로 분리하지 않고 하나의 화면에서 통합 관리하도록 UX를 구성한다.

---

## 6.10 데이터 정책 화면 (관리자)

### 목적
시계열 데이터 보존 및 Downsampling 정책을 설정한다.

### 데이터 정책 적용 범위
* 데이터 정책은 MVP 기준으로 시스템 전역(Global) 정책으로 정의한다.
* 즉, `/admin/policies/data` 에서 설정한 값은 전체 Device 및 전체 시계열 데이터 처리 기준에 공통 적용된다.

## 10. IA 관점에서의 핵심 결정 사항

### 10.1 대시보드를 루트 진입 화면으로 둔다
운영자의 핵심 목표가 실시간 상태 확인이므로, 로그인 후 첫 화면은 대시보드가 가장 적절하다.

### 10.2 설비 상세는 Device 중심 하위 구조로 둔다
시계열 차트, 현재 값, 장애 이력, Tag 정보가 모두 특정 설비를 중심으로 묶이기 때문이다.

### 10.3 관리자 기능은 `/admin` 하위로 분리한다
운영자 중심 모니터링 구조와, 관리자 중심 설정 구조를 정보 구조 차원에서 명확히 분리하기 위함이다.

### 10.4 Tag 설정과 알람 임계값 설정을 통합한다 (UX 최적화)
현장 작업자의 멘탈 모델(센서를 등록하며 즉시 알람 기준을 세움)에 맞추어, 불필요한 페이지 이동(Depth)을 줄이고 작업 피로도를 최소화한다.

### 10.5 예외 화면 및 네비게이션 보조 장치 도입 (UX/보안 최적화)
잘못된 권한의 접근은 403으로 안전하게 차단하며, 관리자 화면의 깊은 Depth에서 길을 잃지 않도록 브레드크럼(Breadcrumbs)을 제공한다.

## 11. 향후 확장 시 고려할 IA 후보

현재 MVP 범위에는 없지만, 이후 확장 시 아래 메뉴를 고려할 수 있다.

* 사용자 관리 / 시스템 로그 / 실시간 이벤트 모니터 / 리포트 및 통계 / PLC 제어 화면 / 알람 룰 템플릿 / 멀티 사이트 및 공장 단위 계층 구조 / 설비별(Device-level) 데이터 정책 / 상세 System Health 모니터링 화면
*(위 항목은 현재 MVP 제외 범위와 구분하여 후속 확장 메뉴로만 고려한다.)*

## 12. 요약

Mini SCADA의 IA는 크게 아래 두 축으로 구성된다.

1. **운영자용 모니터링 축**
   * 대시보드
   * 설비 상세
   * 알람 이력 / 알람 상세

2. **관리자용 설정 축**
   * 설비 관리
   * **Tag/메모리 맵 및 알람 임계값 통합 설정**
   * **데이터 정책**

이 구조는 PRD의 역할 분리와 기능 범위를 그대로 반영하면서도, Usecase의 주요 흐름인 **설비 등록 → 데이터 수집 → 실시간 모니터링 → 알람 대응 → 정책 조정** 흐름이 사용자의 동선 낭비와 시스템 오류 없이 안전하고 자연스럽게 이어지도록 설계하였다.
